How it works — RFID backend flow

Each pass is a passive 13.56 MHz NFC/MIFARE tag (wristband, card, or the phone's NFC). The tag only stores an encrypted UID — never money or access rights. Every decision is validated against Thru Pass's account ledger, so a lost or cloned tag can be killed instantly.

Data model
Account { id, holder, balance } Ticket { id, tier, zones[], status } Tag { uid, account_id, state } ScanEvent { tag, gate, ts, result }
The tag stores only uid + signed token. All rights live server-side, so a tag can be re-linked or revoked without re-issuing hardware.
Offline-first edge
Festival sites drop connectivity constantly. Each reader holds a signed allowlist snapshot and decides locally in <100 ms. Scans write to a local queue and reconcile to the cloud when the link returns — anti-passback state gossips peer-to-peer between gate readers so re-entry fraud is caught even while offline.
Security & fraud
UIDs are meaningless without the server. Tokens are HMAC-signed and rotate per event; cloned or lost tags are added to a real-time blocklist that pushes to every reader in seconds. Cashless top-ups clear against the account ledger, never the tag, so a stolen wristband carries no spendable value.
